# 追句 EchoLine 开发文档

## 1. 产品目标

追句 EchoLine 面向中文母语用户，提供一个“逐句看剧学英语”的学习工作台。用户登录后可以从首页继续学习剧集，通过粗听、精听、逐句循环、跟读评分和“他说上一句，你接下一句”等模式完成每日学习计划，并在进度页查看长期表现。

V1 目标是完整学习闭环，不包含支付、会员、评论社区、公开排行榜和复杂运营看板。

### 1.1 内容与版权策略（V1）

V1 定位为**个人自用**工具，不向公众分发内容：

- 起步只导入**一部剧**，跑通完整学习闭环后再考虑扩充。
- 片源由使用者自行从网络获取，导入后仅供本人学习，不做公开播放或再分发。
- 剧集媒体文件放在服务器本地私有目录，仅通过登录鉴权后的 `/api/media/local/...` Range 接口播放（见第 10 节）。
- “管理员”即使用者本人，负责导入剧集、媒体与字幕。
- 版权风险提示：当前模式以个人学习为限。一旦未来要公开、多用户或商用，必须改为授权片源，或“用户自带片源 / 平台只提供字幕与工作台”的合规模式。

## 2. 技术栈

- Framework: Next.js App Router + TypeScript
- Styling: Tailwind CSS
- UI: shadcn/ui 风格组件 + lucide-react 图标
- Auth: Auth.js 邮箱密码登录 + Linux.do OAuth
- Database: 自托管 PostgreSQL + Drizzle ORM
- Storage: 服务器本地媒体目录，视频和录音均保存为 `local/...` 私有路径
- AI: 服务端可配置 AI Provider，用于录音转写、句子匹配和基础反馈
- Deploy: 自有服务器 Docker Compose（Next.js + PostgreSQL + Redis + Nginx）

## 3. 前端设计要求

UI 必须先执行 `frontend-design` skill，再进入具体实现。

关键要求：

- 第一屏不是营销页，而是学习工作台。
- 学习页是核心界面，播放器、字幕、模式切换和录音反馈必须高效可用。
- 使用图标按钮、Tabs、Toggle、Slider、Menu 等熟悉控件。
- 避免大段功能说明，依赖清晰状态和直接操作。
- 移动端和桌面端都必须检查文本溢出、按钮尺寸、控件重叠和字幕可读性。

## 4. 用户角色

- 游客：只能访问登录页和少量公开介绍信息。
- 普通用户：访问已发布剧集、学习模式、个人进度、学习计划和设置。
- 管理员：维护剧集、集数、媒体文件、字幕和导入任务。

## 5. 核心页面

- `/login`：邮箱密码登录/注册入口，预留 OAuth。
- `/`：首页工作台，展示继续学习、今日计划、最近剧集和学习统计。
- `/series`：剧集列表，支持搜索、难度、题材和进度筛选。
- `/learn/[episodeId]`：学习页，承载全部学习模式。
- `/progress`：学习进度，展示句子、剧集、跟读、连续学习统计。
- `/vocab`：生词本，浏览、搜索、复习从字幕中收藏的单词。
- `/plan`：学习计划，配置每日分钟数、句子数和跟读次数。
- `/settings`：账户、字幕、播放、AI 评分和通知设置。
- `/admin`：管理员内容导入与维护。

## 6. 学习模式与学习功能

### 粗听

- 以整集或片段为单位播放。
- 可切换中英字幕显示。
- 自动保存播放位置。

### 精听

- 按字幕句子切分播放。
- 支持上一句、下一句、慢速播放、单句循环和字幕切换。
- 当前句、上一句、下一句必须清晰可扫读。

### 每句反复听

- 固定当前句 A-B 循环。
- 支持循环次数和播放速度设置。
- 完成后自动记录该句“已练习”。

### 跟读

- 播放原句后开始录音。
- 上传录音到服务端。
- 服务端转写并和目标句比较。
- 返回准确度、完整度、流利度和一句简短建议。

### 他说上一句，你接下一句

- 播放上一句台词。
- 隐藏下一句字幕。
- 用户录音接下一句。
- 系统按目标句评分，并在提交后揭示原句。

### 查词与生词本（跨模式功能）

- 字幕中的英文单词可点击，弹出释义（中文 + 简短英文）。
- 一键收藏到生词本，自动带上当前句作为例句，以及剧集和字幕定位。
- 生词本支持按状态（新词 / 学习中 / 已掌握）和关键词搜索浏览。
- 提供间隔重复复习：每个词记录熟练度、复习次数和下次复习时间，到期进入复习队列。
- 查词与收藏在粗听、精听、逐句循环模式下都可用，不打断播放。

### 释义来源

采用「本地词典 + AI 语境讲解」双层，兼顾速度、成本与上下文质量：

1. **基础词义 —— 本地词典（ECDICT 子集）**：导入开源中英词典到只读表 `dictionary_entries`，提供中文释义、音标、词性和词形还原。离线、免费、毫秒级、无限流。V1 只导入高频词子集，后续可扩充。
2. **语境讲解 —— AI Provider（按需）**：用户点“在这句里什么意思”时，把“单词 + 当前字幕句”发给已配置的 AI，返回结合上下文的中文解释与用法；结果可写入生词本的 `translation`，避免对同一词重复请求。
3. **兜底**：本地词典查不到的词直接走 AI；AI 不可用时提示“暂无释义”，仍允许收藏（`translation` 暂空，之后补全）。

实现说明：

- 查词先按原词精确匹配 `dictionary_entries.word`；未命中时用 ECDICT 的 `exchange`（词形变化）字段做词形还原（如 `running` → `run`）后再查。
- AI 语境讲解按需调用，命中即缓存到生词本，控制调用量。

## 8. API 设计

### 用户接口

- `GET /api/series`：获取剧集列表。
- `GET /api/episodes/:id`：获取单集详情。
- `GET /api/episodes/:id/subtitles`：获取字幕句子。
- `POST /api/progress`：更新播放位置、句子完成度和学习模式进度。
- `POST /api/study-plan`：更新每日学习计划。
- `POST /api/attempts/score`：提交跟读/接句录音并返回评分。
- `GET /api/define`：查询单词释义；先查本地词典，未命中或显式请求语境讲解时回退到 AI（参数含 `word`、可选 `lineId`）。
- `GET /api/vocab`：获取生词本列表，支持状态筛选和搜索。
- `POST /api/vocab`：从字幕收藏一个单词（含例句、剧集、字幕定位）。
- `PATCH /api/vocab/:id`：更新单词的释义、笔记或复习结果（熟练度、下次复习时间）。
- `DELETE /api/vocab/:id`：从生词本移除单词。

### 管理接口

- `POST /api/admin/series`：创建剧集。
- `POST /api/admin/episodes`：创建集数并绑定媒体文件。
- `POST /api/admin/import-subtitles`：上传并解析 SRT/VTT。
- `PATCH /api/admin/subtitle-lines/:id`：编辑句子文本、翻译、时间轴和难度。

## 9. AI 评分契约

### 设计原则：只报告测得准的维度

V1 只有“录音 → 转写文本 → 与目标句比对”这一条链路，因此只能诚实评估**内容是否说对**，无法真正评估发音和流利度（文本相似度测不出口音和节奏）。为避免给出虚假反馈，V1 **完全不展示**发音/流利度评分。

请求输入：

- `mode`: `repeat` 或 `call-response`
- `targetText`: 目标英文句子
- `audioUrl` 或上传的音频文件
- `episodeId`
- `subtitleLineId`

响应输出：

- `transcript`: AI 转写文本
- `accuracy`: 0-100，转写与目标句的词级正确率（说对了多少词）
- `completeness`: 0-100，目标句被说全的比例（= 1 − 漏词率）
- `missedWords`: string[]，漏掉或说错的目标词，供前端高亮
- `overall`: 0-100，V1 仅由 `accuracy` 和 `completeness` 计算，**不含**流利度
- `feedback`: 中文短反馈，聚焦“哪些词漏了/说错了、再试一次”

实现说明：

- V1 评分基于转写文本与目标句的归一化词级相似度、漏词率和长度差，全部可在服务端纯文本计算。
- `repeat_attempts` 表保留 `fluency` 字段，但 V1 始终写 `null` 且不在 UI 出现；待接入专门的发音评测能力后再启用。
- 任何暂时测不准的维度一律不展示，不得伪装成可信分数。

## 10. 权限与安全

- 数据库不暴露公网，浏览器不得直连数据库；所有读写都必须经过 Next.js route handlers。
- 用户权限由服务端应用层鉴权保护：普通接口使用 `requireUserRequest()`，管理接口使用 `requireAdminRequest()`。
- 普通用户只能读取已发布剧集和自己的学习数据。
- 管理员通过 `profiles.role = 'admin'` 判断。
- 剧集媒体默认保存到服务器 `LOCAL_MEDIA_ROOT`，数据库保存 `local/...` 路径，通过登录保护的 `/api/media/local/...` 播放。
- 录音文件可设置生命周期，避免长期占用存储。

## 11. 里程碑

1. 项目初始化：Next.js、Tailwind、依赖、目录结构。
2. 文档和设计：开发文档、frontend-design 产物、schema、环境变量。
3. 基础账户：登录/注册、profile、角色权限。
4. 内容浏览：剧集列表、剧集详情、字幕数据展示。
5. 学习播放器：粗听、精听、逐句循环、播放速度、字幕切换。
6. 进度计划：首页继续学习、今日计划、进度页。
7. 跟读评分：录音、上传、AI mock、评分结果。
8. 生词本：导入词典子集、字幕查词（本地词典 + AI 兜底）、收藏、生词本浏览与间隔重复复习。
9. 管理后台：剧集创建、媒体上传、字幕导入、句子编辑。
10. 验收部署：测试、鉴权检查、数据库迁移和自有服务器 Docker 部署。

## 12. 验收标准

- 用户能从首页进入上次学习位置。
- 剧集列表能筛选并进入学习页。
- 学习页能切换五种学习模式。
- 精听模式能按句操作上一句、下一句、循环和慢速。
- 跟读和接句能提交录音，并展示内容正确率、完整度与漏词反馈（V1 不评估发音/流利度）。
- 能在字幕中点词查义、收藏到生词本，并在生词本中复习到期单词。
- 学习进度和今日计划能更新。
- 管理员能导入字幕并看到导入任务结果。
- 移动端和桌面端核心页面无明显重叠、溢出和不可点击控件。
